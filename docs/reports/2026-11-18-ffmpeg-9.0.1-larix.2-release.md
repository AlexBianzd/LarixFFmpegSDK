# FFmpeg 9.0.1 Larix SDK release 2

This report records the second public LarixFFmpegSDK release. It retains
unmodified FFmpeg 9.0.1 and adds CPU H.264/HEVC encoding and HDR processing.
The tag and release assets remain authoritative; this is a post-publication
verification record.

The six shared libraries are FFmpeg's own libraries. The three external source
dependencies are zimg, x264 and x265; x265's HDR10+ and JSON implementations do not
require separate floating source downloads. ffprobe is a utility, not a library. Windows
also ships exactly six FFmpeg DLL import libraries and seven PDBs; encoder static
archives are not distributed.

zimg uses upstream scalar C++; x265 assembly is disabled. This is a portable CPU
correctness baseline, with no real-time throughput promise. Pinned x265 12-bit is
included to stop normal supported-format probing from loading an unpinned system x265
library. An adversarial loadable-library fixture reproduced that problem in the old
8/10-only package and verifies the final static combination never loads it.

## Verified processing scope

- H.264 Baseline/Main/High 8-bit and High 10; HEVC Main/Main 10 and Main 12.
- Native software encode/decode; delayed frames, B-frame reordering, flushing, frame counts and timestamps; MP4 and Matroska round trips and decoded-frame re-encoding.
- HEVC HDR10 and HLG: color tags, mastering display and content-light metadata where applicable.
- HDR10+: explicit frame-matched x265 JSON input, decoded dynamic metadata and re-encoding with the same controlled input. FFmpeg's x265 wrapper does not automatically forward dynamic HDR frame side data.
- Restricted Dolby Vision 8.1/8.4 compatibility bases plus synthetic RPU decode and re-encode. Compatibility-base handling does not apply Dolby dynamic image mapping.
- CPU zscale/tonemap/exposure filter paths: PQ/HLG to SDR, SDR reference-white conversion to PQ/HLG, numeric black/white levels and monotonic ramps. Obsolete HDR/DV metadata is explicitly removed after pixel changes.

All processing is CPU. No GPU/hardware codec, libplacebo, Vulkan processing, display
renderer, player or screen output is included. Profile 5 image reshaping, complete
profile 7/FEL enhancement-layer processing and Dolby certification are outside this
release. Synthetic metadata/API tests do not establish certified mastering or subjective
grading quality. SDR-to-HDR conversion cannot recover clipped highlight detail.

## Source and license contract

The upstream FFmpeg archive remains byte-for-byte locked, and its patch set is empty.
The LGPL binary profile retains LGPL-2.1-or-later terms, and the GPL binary profile is
GPL-2.0-or-later. Both profiles statically include zimg under its original WTFPL terms.
The GPL profile includes x264/x265 under GPL-2.0-or-later, x265's dynamicHDR10 notice
and bundled json11 MIT notice. Original repository material retains MIT terms; the
repository license does not replace FFmpeg/dependency obligations. Source archives,
original notices, exact configuration, dependency build evidence and SPDX relationships
are part of the release contract.

were used. No paid, larger, private or self-hosted runner, GitHub Packages,

## Verification evidence

All four formal native builds, catalog aggregation, and publication passed in
run 44130976489. Before tagging, the four hosted preflight SDKs and four source
archives also passed exact catalog assembly. The tested implementation tree
and tagged merge tree were identical.

The hosted Windows contract suite ran 127 tests successfully with one
Unix filesystem-alias case skipped; actual SUBST behavior was exercised by
native package construction. The local macOS suite ran 127 tests successfully
with 14 Windows-only skips, including on the merged tree.

Every formal SDK was unpacked and relocated, then used through its installed
CMake package to compile and run the smoke, encoding and HDR consumers. The
smoke consumer checks six library version APIs, demux/decode, RGB/BGR
conversion and audio resampling. GPL acceptance checks all encoding and
metadata cases listed above; LGPL acceptance verifies GPL encoders are absent.
The hostile external-x265 loader fixture must leave no marker file.

CPU filter acceptance checks monotonic ramps and numeric black/white values:
PQ/HLG to SDR 16/235, SDR100 to PQ203 64/573, and SDR to HLG 64/721. These are
controlled reference tests, not subjective grading or performance benchmarks.

After publication, all ten assets were downloaded from their version-specific
public URLs with `GH_TOKEN` and `GITHUB_TOKEN` unset. The complete release
verifier checked the exact inventory, top-level catalog/checksums, all four
source identities, and every SDK's internal manifests, provenance, licenses,
SPDX 2.3 SBOM and file hashes. Verification completed with exit code 0:


The internal manifest and public catalog use schema version 2 and bind the

## Platform boundaries

This release supports Windows x64 MSVC shared SDKs and macOS arm64 shared SDKs
with a macOS 12.0 deployment minimum. It does not claim Windows arm64, MinGW,
macOS Intel/universal2, iOS, Android, Linux, WebAssembly, a static FFmpeg SDK,
Node.js/Python bindings or a player. The Dolby Vision and HDR processing
limitations above remain part of the supported scope.
