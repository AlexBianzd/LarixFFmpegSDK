## Configure contract

Both profiles use this common fail-closed base:

```text
--disable-autodetect --disable-static --enable-shared --disable-doc
--disable-ffmpeg --disable-ffplay --enable-ffprobe
--disable-avfilter --disable-avdevice --disable-stripping
```

The LGPL profile adds no license-enabling argument and explicitly rejects GPL
or nonfree configuration. The GPL profile adds exactly `--enable-gpl`, does
not add `--enable-version3`, and rejects nonfree configuration; its effective
binary license is therefore GPL-2.0-or-later.

Windows adds `--toolchain=msvc --arch=x86_64 --target-os=win64`, the localized
MSVC proxy, reproducible compiler/linker flags, and a relative install prefix.
macOS adds `--arch=arm64 --target-os=darwin --cc=clang`, `@rpath` install
names, macOS 12.0 deployment flags, reproducible prefix maps, and a relative
install prefix. Each archive records the complete ordered argument array in
its manifest rather than relying on this summary.

## Package and provenance contract

Each archive contains shared `avutil`, `avcodec`, `avformat`, `swresample`,
and `swscale` libraries; `ffprobe`; public headers; relocatable
`LarixFFmpegSDK::*` CMake targets; legal/source/configuration provenance; and
canonical metadata. Windows packages also contain MSVC import libraries and
six PDBs. Static libraries and undeclared runtime dependencies are rejected.

The internal release manifest uses schema version 1 and binds the release tag,
packaging revision, source URL/name/size/SHA-256, target ABI and package format,
profile and effective license, complete configure arguments, library ABI
versions, toolchain identity, runtime dependencies, exact file inventory, and
file hashes. Every archive also contains canonical internal `SHA256SUMS` and an
SPDX 2.3 JSON document. The SPDX model distinguishes the Larix SDK aggregate
from the locked upstream FFmpeg source package; SDK licensing combines MIT
repository material with the selected FFmpeg binary license, while the
multi-license upstream source package is conservatively `NOASSERTION`.

The LGPL assets include the applicable LGPL notices. The GPL assets include
GPL-2.0-or-later terms. Both include FFmpeg source/license provenance and the
LarixFFmpegSDK MIT license. Configuration and patch provenance is staged and
verified byte-for-byte; this revision has an empty FFmpeg patch set.

## Verification evidence

All four formal build jobs, catalog aggregation, and publication completed
successfully in run 31777577380. Before packaging, platform inspection proved:

- Windows PE files are x64 MSVC artifacts with an exact allowlisted dependency
  set; PDB inventory and physical-path leakage checks passed.
- macOS Mach-O files are arm64, target macOS 12.0, use SDK-relative `@rpath`
  identities, and depend only on packaged FFmpeg or allowlisted system
  libraries.

Each relocated SDK was unpacked into a new directory, configured through its
installed CMake package, and used to build and run the C smoke consumer. The
consumer exercised all five library version APIs, demux/decode through
`avformat`/`avcodec`, RGB24 and BGR24 conversion through `swscale`, and audio
conversion through `swresample`. Packaged `ffprobe` validated the deterministic
2x2 BGR24 one-frame 25 fps AVI and 48 kHz mono PCM WAV fixtures, including
container, codec, timing, frame count, and audio semantics.

After publication, the anonymous verifier downloaded the public Release
without `GH_TOKEN` or `GITHUB_TOKEN`, checked the exact seven-asset set and
top-level hashes, safely extracted all four SDKs, and revalidated their
internal manifests, provenance, licenses, SPDX documents, and checksums. The
command completed with exit code 0.

## Explicit boundaries

This release verifies only Windows x64 MSVC shared libraries and macOS arm64
shared libraries with a macOS 12.0 minimum. It does not claim support for
Windows arm64, MinGW, static linkage, macOS Intel, universal2, iOS, Android,
Linux, or WebAssembly. Node.js and Python bindings/packages are not part of
this SDK. Future platform drivers have separate target/configuration entry
points, but those platforms require their own builds, packaging rules, and
release evidence before they can be consumed.
